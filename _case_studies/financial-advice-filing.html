01

What this is

A tool for Australian financial-advice firms. It reads client documents (PDF/Word), works out what each one is :Statement of Advice, Record of Advice, Financial Services Guide, Product Disclosure Statement and proposes where to file it and what to rename it, and flags anything it can't confidently place for a human to look at.

It classifies documents that already exist. It does not draft, suggest, or generate financial advice.

  • The knowledge base is the source of truth. Document rules live in knowledge_base.json, never hardcoded in Python.
  • Everything is a proposal. Nothing files itself. Low confidence routes to _Needs review, visibly.
  • Storage stays abstracted. Local folder today, a cloud bucket later — the classifier shouldn't know or care which.
  • Display mode, filing mode, and the classification engine stay independent — none of the three may depend on the others.
  • ROAs have four legislative bases (further advice, hold/no-action, small investment, no buy/sell) — an unresolved ROA is a "confirm which kind" flag, not an error.
02

How it's built

One unit at a time, each one run before the next starts. A unit is a function, a test file, a documented decision — small enough to hold in one head, evaluated by running it or explaining it back, not by trusting a "looks good." Commits land at the end of an evaluated unit, not at the end of a session, so a bad file never has to drag four good ones down with it when something needs undoing.

That's why the timeline below reads the way it does: bug found, fix made, verified against real samples, then move on — rather than a block of "features added" with the reasoning stripped out.

03

Timeline

20–21 Aug

Knowledge base & sample set

knowledge_base.json (v0.3) — document types, classifier hints, filing rules, and the 11-rule edge-case flag set — built first, as the thing everything else reads from. Ten real, verified-native-text sample PDFs sourced across SOA/ROA/FSG/PDS, ground-truthed in sample_documents.labelling.md. harness.py written as a first, keyword-matching prototype of the full pipeline.

Caught & fixed Two ROA samples were stale 2021 versions and one was mislabelled and replaced with current ASIC versions, relabelled nochange (was further_advice).
22 Aug

Live app track begins — parser + scope gate

parser.py (pypdf), app.py (FastAPI, POST /ingest), scope_gate.py (deterministic SOA/ROA/FSG/PDS title check), a drop-zone UI. First end-to-end run of a real PDF through the live track.

Bug 1 — reading order pypdf's default extraction follows content-stream order, not visual order — on FSG_AustralianSuper.pdf a footer interleaved mid-sentence and split a word. Fixed with extraction_mode="layout", verified the title phrase stayed intact across FSG/SOA/ROA/PDS before adopting it.
Bug 2 — cross-reference false positive scope_gate.py first labelled an FSG as soa, because the FSG's own text explains what an SOA is — a legitimate cross-reference, not noise. FSGs mention PDS and SOA; SOAs mention ROA — this is routine in the domain. Fixed by scoring matches by pattern length and restricting the check to the first 500 characters (the title region), not the whole document. Verified against 6 real samples.
25 Aug

Real classifier — Ollama wired in

classifier.py — replaces the scope gate's title-only guess with a real local llama3.1 call via Ollama, grounded in knowledge_base.json's classifier_hints, returning strict {doc_type, confidence, matched_signals}. Verified live against PDS_AustralianSuper.pdf at 100% confidence, correct type.

27 Aug

Status check — unit breakdown written

TO_DO_LIST.md rewritten against the architecture doc: 14 units, ordered by actual data-flow dependency. All 10 sample PDFs re-verified as selectable text directly through parser.py. The git-repo item was logged resolved here — see the next entry.

28 Aug — today

Test suite: 4 files, unit + real end-to-end

tests/test_parser.py, test_scope_gate.py, test_classifier.py (mocked, no Ollama needed), and test_e2e.py — the last one hitting live Ollama on purpose, no mocking, because that's the only test that proves the wired pipeline actually works end to end. README.md updated with the run command and a Windows PATH gotcha (python -m pytest, not bare pytest).

Discrepancy caught TO_DO_LIST.md logged the "no git repo" item as resolved on 27 Aug. It wasn't — git status still returns not a git repository. Flagged rather than trusted; see Open gaps below.
Test bug, found and fixed The out-of-scope e2e fixture used a blank pypdf page with no /Contents stream at all, which crashes layout-mode extraction (KeyError: '/Contents') — a real pypdf edge case, but not the one under test. Fixed with an explicit empty content stream instead.
Timeout fixed, not just changed Live-Ollama runs intermittently timed out at 60s — not cold-start only, failure count varied run to run (1/4, 3/4, 3/4). Bumped classifier.py's requests.post timeout to 180s, then re-ran the full e2e suite to confirm rather than assuming: 5/5 passed, ~2m37s, no timeouts.
Failure log built failure_log.py — log_failure() appends JSON Lines to failure_log.jsonl, field names matching 2_ARCHITECTURE.md's SQLite failure_log table so it drops in later without a schema change. No review UI exists yet to capture human corrections, so tests/test_e2e.py is the current caller — it already has a real prediction and a hand-labelled correct answer for every sample. Unit-tested separately in test_failure_log.py.
Frontend redesigned static/index.html restyled around the PRD's own review vocabulary: confidence as a tiered meter (high / medium / needs review), matched_signals surfaced as an explicit "Why" list, "Proposed classification — confirm before filing" stated up front rather than implied. app.py now resolves doc types to their full names via knowledge_base.json instead of the frontend hardcoding them. Verified live in-browser against a real sample, not just visually reviewed.
Track decision made Live app track has explicit priority. harness.py's fate — kept as an offline validator, or replaced — is deliberately deferred until the live track's results make that call obvious.
31 Aug

Repo goes public — history and backlog on the record

git init, CHANGELOG.md added, README.md filled in with run instructions and a dependency table, first two commits pushed to GitHub. The "no git repo yet" gap logged below on 28 Aug is now closed for real — checked against a fresh git status, not assumed.

Caught during this refresh .gitignore had a bare docs line meant to keep client-filed output out of git, but it also matched this planning folder — docs/BUILD_LOG.html itself included. It was never actually on GitHub despite two pushes. Fixed by scoping the ignore to samples/ only, which is what the "classified documents" comment was actually about.

04

Two build tracks, one now prioritised

Two parallel implementations of the same pipeline exist. As of 28 Aug, the live app track has explicit priority — unit work happens there. harness.py's fate is a deliberately deferred decision, not an accident: it gets made once the live track's results make it obvious, not before.

Live app track

app.py · parser.py · scope_gate.py · classifier.py
  • Single-document, real FastAPI + drop-zone UI
  • Parser → scope gate → live Ollama classifier, all wired
  • Runs against real samples/ PDFs
  • No filing, no flagging engine, no persistence yet

Harness / validation track

harness.py · harness_demo_fixture.json
  • Batch, keyword-matcher prototype
  • Runs against synthetic fixture text, not real samples
  • Two known, unfixed bugs: KB-array-order tie-breaking; string-sorted (not date-parsed) event grouping
  • 11-rule edge_case_flags engine exists in the KB but is read nowhere in code
